# Fintiex SEO: first technical pass, September 11, 2026

## Baseline and implemented changes

The production build contains 454 public indexable HTML pages (excluding the two framework error documents). All already had canonical URLs, descriptions, and one H1. This pass repairs specific crawl and discovery defects rather than rewriting all metadata.

- robots.txt blocked /_next/, which contains scripts and styles used to render the site. Removed that rule; admin and API paths remain excluded.
- Sitemap contained 414 URLs and omitted 40 published pages: 15 calculators, 9 card categories/tools, 7 mortgage pages, and 9 savings account pages. It now covers all 454 public canonical pages.
- Removed build-time lastModified from the sitemap. A deployment is not proof that every page's content changed.
- Removed Article schema's invented default publication date and build-day modification date. Explicit dates supplied by content are retained.
- Fixed 15 broken URL targets in guides, glossary articles, investing pages, and savings review links. Added permanent redirects for old links/bookmarks, and updated internal links directly where authored.
- Differentiated private student-loan and refinancing review titles, resolving the Earnest duplicate title.

## Validation

Run `ANALYTICS_ENABLED=true pnpm --filter @fintiex/web build`, then `python3 scripts/audit-seo.py` from the repository root. The audit checks rendered canonical/title/description/H1 coverage, unique titles, exact sitemap coverage, duplicate sitemap entries, internal destination resolution against built routes/redirects, and rendering asset access. It does not assert rankings, Google indexing, Core Web Vitals, or financial accuracy.

### Search Console evidence and remaining registrar dependency

Report last updated September 4: 198 indexed, 233 not indexed: 92 not-found, 35 redirects, 3 server errors, 3 robots exclusions, 2 soft 404s, 98 crawled but not indexed. These are historical Google counts, not a new live crawl result.

The 3 robots entries are old `/_next/static/media/*.woff2` assets; rendering resources are allowed by the updated robots file. The 2 soft 404s are `/reviews/lendingclub-savings` and `/reviews/synchrony`, now redirected to the corresponding savings details. Obsolete search URLs remain honest 404s. Redirected URLs do not need to be indexed separately.

Most 404 examples use `https://fintiex.com` rather than `https://www.fintiex.com`. The apex resolves to GoDaddy forwarding addresses 15.197.225.128 and 3.33.251.168, nameservers ns59/ns60.domaincontrol.com. A real GET to `/savings/hysa/nevada` on the apex returns 404 before reaching Railway. Middleware already redirects an apex request to the matching www path, but DNS/forwarding must deliver the request to a working redirect service. The signed-in GoDaddy account reports fintiex.com as “Domain not found”; no unrelated domains were changed. Completion requires access to the GoDaddy account holding this domain, then an HTTPS permanent redirect preserving every path and query (or correct Railway apex domain/DNS configuration). Verify several deep URLs before asking Google to validate the 404 group. Do not redirect all missing pages to the homepage.
